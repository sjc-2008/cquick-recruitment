## 任务 1：颜色目标检测

### 目标颜色

支持三种颜色：橙色（orange）、红色（red）、紫色（purple）。

### HSV 阈值

| 颜色 | HSV 下界 | HSV 上界 | 说明 |
| --- | --- | --- | --- |
| 橙色 | (5, 120, 120) | (25, 255, 255) | 单段 |
| 紫色 | (130, 80, 80) | (165, 255, 255) | 单段 |
| 红色 | (0, 120, 120) / (170, 120, 120) | (10, 255, 255) / (179, 255, 255) | 两段（跨越色相环两端） |

### 最小轮廓面积

默认 500（像素平方）。

### 中心点计算方法

使用轮廓矩（`cv2.moments`），`u = m10/m00`，`v = m01/m00`。当 `m00 == 0` 时回退到外接矩形中心。

### 多目标选择规则

按轮廓面积降序排序，选择面积最大的目标。

### 测试图片结果

| 图片 | 颜色 | 检测结果 | 中心点 (u, v) | 面积 |
| --- | --- | --- | --- | --- |
| 01_orange_clear | 橙 | 检测到 | (320, 239) | 25648.5 |
| 01_red_clear | 红 | 检测到 | (320, 239) | 25719.0 |
| 01_purple_clear | 紫 | 检测到 | (319, 239) | 25858.0 |
| 02_orange_small | 橙 | 检测到 | (320, 240) | 2023.0 |
| 03_purple_similar_bg | 紫 | 检测到 | (319, 240) | 15564.5 |
| 04_red_with_orange | 红 | 检测到 | (319, 240) | 20284.0 |

所有图片目标中心都在图像中心 (320, 240) 附近，符合生成时的设定。

### 失败原因分析

1. **光照变化**：HSV 的 V（明度）和 S（饱和度）受光照影响大，过暗或过亮会超出阈值范围。
2. **背景同色**：背景出现与目标相近颜色时，会被一起分割出来，需靠面积筛选或更严格的阈值区分。
3. **反光**：目标表面的高光会改变局部颜色，导致 mask 出现空洞。
4. **遮挡**：目标被部分遮挡时，轮廓不完整，中心点会偏移。

## 任务 2：可视化与参数对比

### 可视化内容

在输出图上标注：目标轮廓（绿色）、中心点（红色十字 + 圆点）、坐标文字（`u=..., v=...`）、面积文字（`area=...`）。未检测到时在图上标注 "NOT DETECTED"。

### 参数对比实验

以下以 `04_red_with_orange.png`（红色目标 + 橙色干扰）为例：

| 用例 | 参数 | 结果 |
| --- | --- | --- |
| 基准 | min_area=500, morph=True | u=319, v=240, area=20284 |
| 提高最小面积 | min_area=5000, morph=True | u=319, v=240, area=20284 |
| 关闭形态学 | min_area=500, morph=False | u=319, v=240, area=20286 |

**现象分析**：

- 提高最小面积到 5000 后，结果不变，说明这张图里噪声块面积都小于 5000，面积筛选有效过滤了噪声但未误删目标。
- 关闭形态学后面积从 20284 变为 20286（略增），说明开运算去掉了目标边缘少量毛刺像素，形态学对轮廓完整性有细微影响。

### 误检案例

`03_purple_similar_bg.png` 中背景含两个相近紫色干扰块。若把 HSV 阈值放宽（紫色范围扩大到更浅的紫），干扰块也会被检测到。默认阈值下，干扰块颜色不够纯，未被纳入，只选中中心目标。

### 漏检 / 定位偏差案例

若最小面积阈值设得过大（超过目标面积），目标会被当作噪声过滤掉，导致漏检。若目标被部分遮挡，轮廓中心会偏离真实中心，产生定位偏差。

### 像素坐标 vs 真实坐标

像素坐标 `(u, v)` 以图像左上角为原点，u 向右增大、v 向下增大，只表示目标在图像中的位置，**不是机器人世界坐标，也不是米制距离**。要转换到场地/机器人坐标，需要相机标定和几何关系，本周不涉及。

## 任务 3：ROS2 通信（代码已写，待 Ubuntu 环境运行）

### 消息字段

`TargetPosition.msg`：

```text
bool    detected   # 本帧是否检测到目标
float32 u          # 目标中心横坐标（像素）
float32 v          # 目标中心纵坐标（像素）
float32 area       # 目标轮廓面积（像素平方）
```

### 话题名

`/target_position`

### 发布 / 订阅流程

1. 创建 `ament_cmake` 接口包，定义 `TargetPosition.msg`；
2. 在 `package.xml` 和 `CMakeLists.txt` 声明消息生成依赖；
3. 编译后 `ros2 interface show` 检查字段；
4. 发布节点把视觉检测结果（detected/u/v/area）发布到 `/target_position`；
5. 订阅节点订阅并打印。

### 实际检测结果如何接入

发布节点调用 `color_detect.detect()` 得到 `detected/u/v/area`，填入消息后发布。未检测到目标时 `detected=false`，u/v/area 为 0，用 `detected` 字段判断有效性，避免把"没检测到"误当成目标在左上角。

## 问题与解决过程

**问题**：`visualize.py` 运行时 `ModuleNotFoundError: No module named 'color_detect'`。

**排查**：脚本运行时，Python 的 `sys.path` 不包含脚本所在目录，导致无法导入同目录的 `color_detect.py`。

**解决**：在 `visualize.py` 开头加入 `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))`，把脚本目录加入搜索路径。
